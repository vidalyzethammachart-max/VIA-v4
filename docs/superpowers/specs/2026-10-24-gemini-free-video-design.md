# ร่าง: เปลี่ยน Analyze Video เป็น Gemini Free Tier

วันที่: 24 ตุลาคม 2026 — Asia/Bangkok

สถานะ: ผู้ใช้อนุมัติเริ่มปรับเมื่อ 24 ตุลาคม 2026

เพิ่มเติม 25 ตุลาคม 2026: ผู้ใช้ยืนยันว่า hosting ต้องไม่เพิ่มค่าใช้จ่ายด้วย
และอนุมัติให้รัน backend บนเครื่องนี้ผ่าน ngrok Free เปิดเฉพาะ POST
`/api/analyze-video` พร้อม service token โดยรับทราบว่าข้อมูลผ่าน ngrok
และต้องเปิดคอมค้างไว้ จึงเปลี่ยนขั้น deployment เป็น local runtime
รายละเอียดและผลทดสอบอยู่ที่ `docs/local-gemini-analysis.md`

## เป้าหมายและขอบเขต

ให้ขั้น Analyze Video ทำงานได้โดยไม่ต้องเติมเครดิต OpenAI และไม่เพิ่มค่า API
ใช้ Gemini project ที่ตรวจยืนยันว่าเป็น Free Tier และรุ่นที่มีโควตาฟรีจริง
ร่างนี้ไม่รับรองค่าใช้จ่ายรวมของ Cloud Run, R2, Supabase หรือ n8n เป็นศูนย์
ต้องตรวจต้นทุน deployment และ hosting ก่อนดำเนินการที่อาจคิดเงิน

เปลี่ยนเฉพาะการวิเคราะห์วิดีโอรายครั้ง คงคะแนนมนุษย์ รูปแบบ JSON และการส่งต่อ
เพื่อสร้างเอกสารเดิมไว้ ขั้นรวมผลที่ backend ยังใช้ OpenAI อยู่นอกขอบเขตรอบนี้
จึงยังอาจติดเครดิตหากเรียกฟังก์ชันรวมผลนั้น

## ทางเลือกที่พิจารณา

1. Gemini Free Tier: แนวทางที่เสนอในร่างนี้ ใช้ระบบออนไลน์เดิมและ adapter
   ที่มีใน repo ได้ แต่ต้องตรวจสิทธิ์ โควตา และความเหมาะสมของข้อมูลก่อน
2. AI บนเครื่องเดิม: ไม่มีค่าบริการ API แต่ต้องเปิดเครื่องและตรวจสเปก/คุณภาพ
   ผู้ใช้ขอรายละเอียดแนวทางที่ 1 ก่อนเริ่มปรับ จึงยังไม่ดำเนินการแนวทางนี้

## การทำงานที่เสนอ

อัปโหลดวิดีโอเต็มเข้า R2 → Edge Function → n8n → backend ดาวน์โหลดวิดีโอ
→ ffmpeg แยกภาพตัวอย่างประมาณ 6 ภาพและเสียง MP3 → Gemini วิเคราะห์ร่วมกัน
→ ตรวจผล JSON → n8n สร้างรายงาน → callback → ตรวจ PDF/DOCX

ผู้ใช้ไม่ต้องตัดวิดีโอก่อนอัปโหลด รอบแรกยังไม่แบ่งคลิปเป็นหลายช่วง
และไม่อ้างว่า AI ตรวจทุกเฟรม ภาพตัวอย่างอาจพลาดเหตุการณ์ระหว่างภาพได้
หากหลักฐานไม่พอให้ระบุข้อจำกัด ถ้าไม่มีเสียงต้องไม่สร้างคะแนนเสียงขึ้นเอง
หากขนาด media เกินข้อจำกัด ให้แจ้งข้อผิดพลาดและหยุด ไม่ตัดหลักฐานทิ้งเงียบ ๆ

## ขั้นตอนก่อนและหลังเริ่มปรับ

### 1. ยืนยัน Free Tier และข้อมูลที่ส่งได้

- แก้ปัญหาสิทธิ์ AI Studio ที่ปัจจุบันตอบ permission denied
- ตรวจ project, tier, model และโควตาที่ใช้ได้จริง ยังไม่เรียก inference
- เสนอใช้ project สำหรับ Gemini แยกจาก project ที่โฮสต์ Cloud Run
  ไม่ปิด billing ของ project hosting เดิมเพื่อพยายามให้ Gemini ฟรี
- เจ้าของบัญชีจัดเตรียม API key ผ่านช่องทางเก็บ secret ฝั่ง server
  ไม่ส่ง key ในแชตหรือบันทึกใน Git
- ตรวจเงื่อนไขข้อมูลของ Unpaid Services กับชนิดวิดีโอที่จะใช้จริง
  หากมีข้อมูลส่วนบุคคล ข้อมูลลับ หรือข้อมูลอ่อนไหว ให้หยุดทบทวนทางเลือก
  ไม่ถือว่าการอนุมัติร่างนี้อนุญาตให้ส่งข้อมูลทุกประเภท

### 2. เตรียมการเปลี่ยน backend แบบจำกัดขอบเขต

- ใช้ revision/source ที่ยืนยันแล้วว่า n8n เรียกจริงเป็นฐานเปรียบเทียบ
- ทบทวน Gemini adapter, schema validator, provider selector และ dependencies
  ที่มีใน repo และเลือกเฉพาะสิ่งจำเป็น ไม่ deploy ทุกความต่างใน checkout
- ระบุ `VIDEO_ANALYSIS_PROVIDER=gemini` และ `GEMINI_MODEL` ชัดเจน
  รุ่นเริ่มต้นที่เสนอคือ `gemini-2.5-flash` โดยตรวจสิทธิ์จริงอีกครั้งก่อนใช้
  ไม่พึ่งค่า default ปัจจุบันของ adapter ที่เป็นคนละรุ่น
- เก็บ key ฝั่ง server รักษา analysis service token และ R2 configuration
- ตรวจผลลัพธ์ให้ตรงกับสัญญาเดิม โดยเฉพาะ `analysis.evaluation`
  และ metadata provider/model ไม่แก้หรือเฉลี่ยคะแนนมนุษย์ร่วมกับคะแนน AI

### 3. คุมโควตาและผลล้มเหลว

- ไม่มี fallback ไป OpenAI, Qwen หรือ model เสียเงิน
- ไม่มี automatic replay หรือ retry วนเมื่อเจอ quota/billing error
- แยก error key/model/quota/billing/timeout และไม่บันทึก secrets หรือ signed URL
- ใช้ cache ผลสำเร็จและ duplicate guard ที่มีอยู่ เมื่อ delivery ไม่แน่นอน
  ต้องตรวจ execution/usage ก่อนทำซ้ำ
- หากโควตาฟรีหมดให้หยุดและแจ้งเหตุผล การรอหรือส่งใหม่ต้องผ่านการตรวจสถานะ
  ไม่เพิ่ม queue/scheduler ใหม่ในขอบเขตรอบนี้
- ถ้า node รายงานอื่นใช้ Gemini project เดียวกัน ต้องนับโควตาร่วมด้วย
  ไม่ประเมินจำนวนแบบต่อวันจากโควตาของ Analyze Video เพียงขั้นเดียว

### 4. ทดสอบในเครื่องก่อน deploy

- ทดสอบด้วยภาพ/เสียงจำลองและ mock inference โดยไม่ใช้โควตาหรือข้อมูลจริง
- ครอบคลุมวิดีโอมีเสียง ไม่มีเสียง ผล JSON ผิดรูปแบบ โควตาหมด และ key ผิด
- ตรวจ metadata, คะแนนมนุษย์, target identity และเส้นทางสร้างเอกสาร
- รันชุดทดสอบที่เกี่ยวข้อง รวมถึง checks ของโปรเจกต์ตามส่วนที่เปลี่ยน

### 5. Deploy และตรวจแบบไม่สร้างงาน

- ตรวจว่า build, registry และ Cloud Run อยู่ในงบ/โควตาที่ไม่เพิ่มค่าใช้จ่าย
  หากยืนยันไม่ได้ ให้รายงานก่อน ไม่อ้างว่า deploy ฟรี
- เมื่อผ่านข้อกำหนดแล้ว เตรียม revision และ secret สำหรับ Gemini
- ให้ n8n เรียก revision ที่ตรวจแล้ว รักษา Header Auth, timeout,
  Retry On Fail OFF และ Webhook Respond Immediately
- ตรวจ health, authentication และ validation ที่ไม่เรียก AI ก่อน
- จากนั้นจึงเรียก Gemini ด้วย media จำลองขนาดเล็กหนึ่งครั้ง
  เฉพาะหลังยืนยัน Free Tier การตอบ model metadata หรือ cache hit ยังไม่พอ

### 6. ทดสอบงานจริงหนึ่งรายการ

- ตรวจ execution เดิม สถานะเอกสาร และ dispatch guard อีกครั้ง
- ระบุ target สำหรับทดสอบให้แน่ชัด ไม่สมมติว่าให้ส่งแบบ 003 ทันที
- ตรวจความพร้อมของไฟล์และอายุ signed URL ก่อนเริ่ม
- ส่งครั้งเดียว ติดตาม AI → report → callback → ดาวน์โหลด PDF/DOCX
- เปรียบเทียบเนื้อหาและคะแนนกับหลักฐาน ไม่ใช้เพียง HTTP 200 เป็นเกณฑ์ผ่าน
- ไม่ลบ guard, สร้างแบบแทน หรือ replay งานเดิมเพื่อให้ผลดูสำเร็จ

## เกณฑ์รับงาน

- ยืนยัน Free Tier และโควตาจริงของ project ที่ใช้ได้
- media จำลองผ่านทั้งภาพและเสียงโดยไม่มีการเรียก provider เสียเงิน
- งานจริงที่ระบุไว้สำเร็จ ได้เอกสารที่เปิดได้ และคะแนนมนุษย์ยังตรงเดิม
- โควตาหมดแล้วหยุดอย่างชัดเจน ไม่มีการคิดเงินผ่าน fallback หรือส่งงานซ้ำ
- บันทึก provider/model/revision/execution และข้อจำกัดโดยไม่มี secrets

## ความเสี่ยงและสิ่งที่ต้องตัดสินใจก่อนเริ่ม

- โควตาฟรีอาจไม่พอกับงานพร้อมกันหรือคลิปยาว ต้องตรวจใน project จริง
- Free Tier มีเงื่อนไขการนำ input/output ไปปรับปรุงผลิตภัณฑ์และการตรวจโดยคน
  ต้องพิจารณาความเหมาะสมของวิดีโอสำหรับ VIA V4 ก่อนส่ง
- คะแนนและคำอธิบายอาจต่างจาก OpenAI ต้องตรวจคุณภาพภาษาไทยและ rubric
- ค่า hosting/storage/build แยกจากราคา Gemini API
- ต้องยืนยันว่ารอบนี้จำกัดเฉพาะ Analyze Video และยังไม่ย้ายขั้นรวมผล OpenAI

## ย้อนกลับเมื่อทดสอบไม่ผ่าน

เก็บค่า workflow และ revision เดิมไว้ หาก Gemini ไม่ผ่าน ให้หยุดใช้ revision ใหม่
และคืน endpoint/config เดิมโดยไม่เรียก inference หรือ replay งานอัตโนมัติ
การคืนค่า OpenAI ไม่ได้แก้เครดิตหมด และไม่ถือเป็นการอนุญาตให้ใช้งานเสียเงิน
