# แบบประเมินกลุ่มวิดีโอ (รวมหลายแบบประเมินเป็นผลกลุ่ม) — Design

วันที่: 2026-11-11 · สถานะ: รอผู้ใช้ตรวจสเปก

## เป้าหมาย

ในหน้ากลุ่มวิดีโอ (`/video-cases`) ผู้ใช้ (หัวหน้าเคสหรือแอดมิน) เลือกแบบประเมินตั้งแต่ 2 ใบขึ้นไป
รวมคะแนนและข้อมูลอื่นๆ ออกมาเป็น "แบบประเมินกลุ่มวิดีโอ" (9 หมวด 45 ข้อ) ที่ AI สรุปรวมใหม่
และสร้างเอกสาร PDF/DOCX ได้ ใบต้นทางไม่ถูกแก้หรือลบ

## ปัญหาปัจจุบัน (จากการอ่านโค้ด)

1. รวมได้ 1 ใบ (`VideoCaseDetailPage.tsx` ~บรรทัด 174, `videoCaseService.ts` ~บรรทัด 385 เช็คแค่ `length === 0`)
2. ขั้นเลือก/รวมอยู่ที่ `/video-cases/:id` ไม่ใช่หน้า `/video-cases`; ใน `VideoCasesPage.tsx` เหลือโค้ดรวม/ลบที่ไม่มีปุ่มเรียกใช้
3. ~~`combineNestedValues` ... ข้อความใช้แค่ค่าแรก และ `notes` รายคนไม่ถูกส่งต่อ~~ **แก้ไข (2026-11-11):** ค่า `rubric` เป็นตัวเลขล้วน และ `buildVideoCaseSummaryPayload` ส่ง `suggestions` ให้ n8n อยู่แล้ว สิ่งที่ขาดจริงคือการผูกข้อเสนอแนะกับผู้ประเมิน (`evaluators`) และร่างข้อเสนอแนะรวมให้ผู้ใช้ ดู `docs/superpowers/plans/2026-11-11-video-group-evaluation.md`
4. ผลลัพธ์เป็นผลเฉลี่ยตัวเลข (`ai_model: null`) ผู้ใช้ต้องเขียนข้อเสนอแนะรวมเองจากศูนย์

## แนวทางที่เลือก: A — ย้ายขั้นเลือก/รวมมาที่ `/video-cases` และต่อยอดหน้าสรุปเดิม

ไม่สร้างแถวใน `evaluations` (ไม่กระทบ dashboard, ลำดับ # และ RLS) ผลรวมยังเป็นแถวใน `video_case_aggregates`
และใช้ `forward-to-n8n` เดิมสร้างเอกสาร ไม่แก้ n8n workflow ในรอบนี้ (เปลี่ยนเฉพาะ payload)

## การเปลี่ยนแปลง

### 1. หน้า `/video-cases`
- การ์ด "เคสที่เลือก" เพิ่มรายการแบบประเมินของเคส พร้อมช่องติ๊ก (ผู้ประเมิน, วันที่, สถานะ)
- ติ๊กได้เฉพาะ `document_status === "ready"` (ใช้ `videoCaseCombineSelectionCore.js`)
- ปุ่ม "รวมเป็นแบบประเมินกลุ่ม" เห็นเฉพาะหัวหน้าเคส/แอดมิน กดได้เมื่อเลือก ≥ 2 ใบ ไม่ถึงให้แสดงเหตุผลใต้ปุ่ม
- ค่าขั้นต่ำ (2) กำหนดและตรวจในฟังก์ชันเดียวใน `videoCaseCombineSelectionCore.js` ใช้ร่วมกันทั้ง UI และ `combineVideoCaseAnalyses`
- ลบโค้ดค้างใน `VideoCasesPage.tsx` ที่ไม่ใช้ (`handleDeleteEvaluation`, `prompt` ฯลฯ) ตามที่ย้ายแล้ว
- `/video-cases/:id` ยังเป็นหน้ารายละเอียดและประวัติผลรวม

### 2. การรวมข้อมูลให้ครบ
- คะแนนรายข้อ/รายหมวด: เฉลี่ยเหมือนเดิม (ค่าว่างไม่นับเป็น 0)
- ข้อความ: เก็บเป็นรายการจากทุกใบพร้อมชื่อผู้ประเมิน แทนการเอาค่าแรก
- `source_snapshot` เก็บข้อเสนอแนะรายคนครบ
- ใบต้นทางไม่ถูกแก้ ผลรวมเป็นแถวใหม่ใน `video_case_aggregates`

### 3. ผลลัพธ์เป็นแบบประเมิน + AI สรุปรวมใหม่
- หน้า `/video-cases/:id/summaries/:summaryId` ใช้ชื่อ "แบบประเมินกลุ่มวิดีโอ" แสดง 9 หมวด 45 ข้อด้วยคะแนนรวม และรายชื่อผู้ประเมินที่ถูกรวม
- ช่อง "ข้อเสนอแนะโดยรวม" เติมล่วงหน้าจากข้อเสนอแนะทุกใบ แก้ไขได้ก่อนส่ง
- ส่งผ่าน `forward-to-n8n` เดิม payload เพิ่มรายชื่อผู้ประเมินและข้อเสนอแนะรายคน
- field เดิมใน payload ต้องอยู่ครบ (n8n workflow เดิมต้องไม่พัง)
- การกันส่งซ้ำใช้กลไก server เดิม (`document_status`)

## Error handling
- รวมไม่สำเร็จ: แสดงข้อความไทยในกล่องแดงเดิม ไม่ navigate และคืนสถานะ "กำลังรวม" ใน `finally`
- ผู้ที่ไม่ใช่หัวหน้า/แอดมินไม่เห็นปุ่ม; RLS `video_case_aggregates_insert_leader` เป็นด่านสุดท้าย (มีอยู่แล้ว)
- กดรวมซ้ำสร้างผลรวมใหม่ได้ (เป็นประวัติ) ปุ่มปิดระหว่างทำงาน

## ข้อสมมติและสิ่งที่ยังไม่ยืนยัน
- สมมติว่า "แบบประเมินกลุ่มวิดีโอ" มีโครงสร้างเดียวกับแบบประเมินรายคน (9 หมวด 45 ข้อ) — ผู้ใช้ยังไม่ได้ยืนยันตรงๆ
- ยังไม่ได้อ่าน `buildVideoCaseSummaryPayload` และ n8n workflow จริง: ต้องตรวจตอนเขียนแผนว่า AI ใช้ payload ที่เพิ่มได้เลยหรือต้องแก้ prompt ฝั่ง n8n
- ผู้ใช้ยังไม่ตอบว่าแก้ n8n workflow ได้หรือไม่ จึงออกแบบแบบไม่แตะ workflow
